# 7장 동시성 측정 (./gradlew concurrencyMeasurement, 커밋 c2c8e75 위 측정 코드 — 결정 1·2·3·5 가 모두 들어간 코드에서 결제를 바꾸려고 읽는 저장소만 구현마다 바꿈)
# [잠금 방식] 같은 결제에 동시 요청 N개(10, 30)를 스레드 N개에서 래치로 한꺼번에 보낸다. 트리거로 겹침을 고정하지 않는다. 카드사는 바로 답한다.
#   취소: 승인된 15000원 결제에 1000원 부분 취소 N개(Idempotency-Key 는 모두 다름) — 15개까지만 남은 금액 안이다.
#   같은 키 승인: 준비한 결제에 같은 결제 키 승인 N개. 결정 2 가 들어간 코드라 인증 상태에 다시 온 같은 키는 AUTHENTICATED(API 202)로 답한다.
#   {답별 개수}: 답한 것은 취소 상태(DONE 끝남, FAILED 카드사 거절)나 결제 상태, 받지 않은 것은 오류 코드(INVALID_PAYMENT_TRANSITION 은 변경 번호·상태 조건이 어긋난 409 포함).
#   응답 ms 는 요청마다 서비스가 답할 때까지(중앙값, 최댓값). 묶음마다 결제 3건(#1~#3). 묶음 전에 N=5 취소를 한 번 버린다.
#   "우리 남은 금액"은 결제 금액 − 끝난 취소의 합(보정 전). 변경 번호 비교의 카드사 잔액과 우리 남은 금액 차이는 그 상태 그대로 적었다.
# [서버 수] 서버 1·2·3대(시험 JVM 안에 같은 MySQL·Mock PG 를 쓰는 결제 서버를 더 띄움)가 래치로 같은 때 승인 보정 주기를 한 번 돌린다.
#   대상은 결과 모름 결제 20건(카드사는 모두 승인), 카드사는 조회에 0.1초 늦게 답한다. 묶음마다 2번. 카드사 조회는 20건의 조회 횟수 합.
#   "주기 한 번"은 모든 서버가 그 주기를 마칠 때까지.
# 구현 순서는 실행 순서 그대로다. 실행 환경은 environment.md. 한 번 실행한 값이다.
