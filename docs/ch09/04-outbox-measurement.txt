# 9장 결제 이벤트 측정 (./gradlew outboxMeasurement). 실행 환경은 environment.md.
# 가. 보내는 방식마다(EventDeliveryMeasurement): 결제 60건을 스레드 3개에서 0.2초 간격으로 승인하고 바로 전액 취소한다(결제마다 승인·취소 두 이벤트, 모두 120건).
#     시작 1초 뒤부터 4초 동안 브로커를 끊는다(중계, 시험 보내기 시간 제한 3초). 끝난 뒤 보낼 것이 남지 않고 주문 서비스가 받은 수가 3초 동안 그대로일 때까지 기다려 센다.
#     키 없이 보내는 방식도 기본 파티셔너를 그대로 쓴다. 릴레이는 0.1초마다 돈다. 방식마다 3번(#1~#3), 앞에 끊지 않은 결제 6건 묶음을 한 번 돌려 버린다.
# 나. 릴레이를 나누는 방식마다(RelayThroughputMeasurement): 결제 100건을 승인 뒤 전액 취소해 보낼 결과 200건을 쌓아 두고(릴레이 꺼 둠), 서버 두 대가 같은 때
#     릴레이를 쉬지 않고 돌려 보낼 것이 없어질 때까지 잰다. 브로커는 끊지 않는다. 주기 하나는 50건까지(한 줄씩 나눠 보내기는 한 줄씩). 방식마다 3번, 앞에 5건 묶음을 버린다.
#   유실: 결제마다 가야 할 두 결과(승인, 승인 취소) 가운데 한 번도 오지 않은 수. 중복: 받은 수 − 받은 서로 다른 결과 수.
#   순서 위반 결제: 취소를 받은 뒤에 승인을 (다시) 받은 결제 수. 주문 상태 어긋남: 주문 상태가 CANCELED 가 아닌 결제 수.
#   도착 지연: 결과마다 처음 받은 것의 (주문 서비스가 받은 때 − 결제 서버가 이벤트를 만든 때). 나.에서는 쌓아 두는 동안 기다린 시간이 들어 있어 방식끼리만 견준다.
#   승인·취소 응답: 결제 서버 서비스가 답할 때까지. 결제를 보낸 시간: 결제 60건을 모두 보낸 때까지(바로 보내는 방식은 끊긴 동안 답을 기다리느라 늘어난다).
#   다 보낸 시간: 두 서버가 릴레이를 시작한 때부터 둘 다 보낼 것이 없다고 멈춘 때까지. 처리량: 200 / 다 보낸 시간.
# 두 번 실행했다(같은 코드, 첫 실행의 한 줄씩 나눠 보내기 도착 지연은 그 비교 구현이 만든 때를 9시간 어긋나게 읽어 버리고 고친 뒤 다시 잰 값만 쓴다 — 아래 첫 실행에 그대로 남김).
