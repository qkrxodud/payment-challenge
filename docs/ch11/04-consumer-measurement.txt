# 11장 소비자 측정 (./gradlew consumerMeasurement). 실행 환경은 environment.md. 측정 코드: ConsumerMeasurement(방식마다 하위 클래스).
# 대상: 주문 서비스(결제 결과 소비자). 다시 시도 간격·횟수는 운영 값 1·2·4·8초(합 15초)이고, 비교 구현도 같은 값을 쓴다(기본 처리만 FixedBackOff(0, 9)).
# 가. 받는 쪽 저장소 장애: MySQL 을 10초 또는 30초 읽기 전용으로 돌리고, 그동안 0.5초마다 새 결제의 승인 결과를 하나씩 싣는다(10초 → 20건, 30초 → 60건,
#     키가 다른 결제라 파티션 2개에 흩어짐). 장애를 걷은 뒤 모두 반영되거나 실패 모음에 남을 때까지(최대 60초) 기다리고 2초 더 본다.
#     반영: 주문이 바뀐 수. 실패 모음: <토픽>.DLT(DB 실패 표 방식은 failed_message)에 남은 수. 잃음: 둘 다 아닌 수.
#     반영 지연 ms: 결과를 토픽에 실은 때(브로커 시각)부터 주문 서비스가 받아 남긴 때까지(반영된 것만, 중앙·p95·최대).
# 나. 막는 시간: 한 결제의 결과가 계속 쓰이지 못하게(트리거 — 일시 오류로 분류) 한 채 그 결과를 싣고, 바로 뒤에 같은 파티션의 다른 결제 결과를 싣는다.
#     뒤 결과가 반영되기까지 걸린 ms. 모르는 결제 상태(영구 오류) 뒤에 실은 결과도 같은 방법으로 쟀다.
# 방식마다 3번(#1~#3), 두 번 실행했다(같은 코드, 첫 실행 2026-11-22 새벽, 두 번째 실행은 후속 작업으로 같은 날). 측정 전에 한 건을 먼저 반영해 둔다(기록 안 함).
