# 4장 결과 모름 보정 측정을 6장 코드(보정 해석 변경 뒤, 커밋 83013dd)에서 다시 돌린 값 (./gradlew reconciliationMeasurement)
# 4장 시점 기록은 docs/ch04/04-reconciliation-measurement.txt 다. 이 파일은 그것을 바꾸지 않고 6장 코드에서 다시 잰 값이다.
# 6장에서 바뀐 것: 4장 보정이 웹훅과 같은 카드사 조회·따라가기로 닫는다(카드사 승인 뒤 취소 CANCELED → 승인 취소, 4장은 승인 실패).
#   측정의 카드사 짝도 같이 바뀌었다: DONE ↔ 승인, CANCELED ↔ 승인 취소, 그 밖(ABORTED·기록 없음) ↔ 승인 실패(4장은 DONE 이 아니면 모두 승인 실패).
# 조건은 4장과 같다. 결제 12건: 카드사가 1.5초 뒤 승인 4건, 1.5초 뒤 거절 3건, 승인 요청이 닿지 않음(LOST) 3건, 카드사 승인 뒤 결과 기록 실패(MySQL 트리거) 2건.
# 승인 읽기 시간 제한 1초. 카드사가 처리를 마친 뒤 보정을 돌리고, 보정에 넘기는 시각은 보정 대기 시간(10초)이 지난 때로 준다.
# 따라서 아래 시간에는 보정 대기 시간과 주기(interval)가 들어 있지 않다. 운영에서는 wait-after-request + interval 이 더해진다.
# "첫 보정의 확인 요청에 늦게 답함": 첫 보정 동안만 카드사가 조회·취소에 1.5초 뒤 답한다(읽기 시간 제한 1초를 넘김). 둘째 보정부터 바로 답한다.
# 보정은 미확정 결제(인증·결과 모름)가 남아 있으면 최대 5번까지 돌린다. 비교 B·C 는 보정이 없어 5번 모두 아무것도 하지 않은 시간이다.
# 구현 순서는 실행 순서 그대로다. 실행 환경은 environment.md. 한 번 실행한 값이다.
