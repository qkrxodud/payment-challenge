# 10장 Saga 측정 (./gradlew sagaMeasurement). 실행 환경은 environment.md.
# 가. 방식마다(SagaMeasurement): 재고 20개 상품에 주문을 한 건씩 차례로 보낸다 — (가) 보통 10건 → (나) 재고 서비스가 답을 1.5초 늦게 주는 동안 10건
#     (결제 서버 재고 시간 제한은 운영 값 연결 300ms·읽기 1s) → (다) 재고 서비스가 멈춘 동안(중계 끊음 + 재고 명령 읽기 멈춤) 10건, 그리고 승인된 결제 5건 전액 취소
#     → 재고 서비스를 되돌리고 20초까지 기다린다. 릴레이는 운영처럼 0.5초마다 돈다. 카드사는 바로 승인한다. 방식마다 3번(#1~#3), 앞에 1건을 버린다.
#   응답 ms: 결제 준비 + 승인 요청이 답할 때까지(가·나·다 구간마다 중앙·p95·최대, 10건씩).
#   승인 답: 고객이 받은 승인 답 수(뒤에 보상 취소된 것 포함). 넘겨 판 수량: 끝난 뒤 승인이 남은 결제의 수량 − 처음 재고(0 보다 작으면 0).
#   어긋난 재고: 20초 뒤 (남은 재고 + 승인이 남은 결제의 수량) − 처음 재고. 음수는 끝내 돌아오지 않은 재고, 양수는 처음보다 늘어난 재고.
#   맞춰진 때: 재고 서비스를 되돌린 때부터 남은 재고 + 승인 수량이 처음 재고와 같아질 때까지(100ms 마다 봄, 20초 안에 안 되면 "안 맞음").
#   원복 ms: 승인 없이 끝나거나 취소된 결제마다 그 승인·취소 요청을 보낸 때부터 재고 서비스가 그 예약을 해제한 때까지(중앙·p95·최대). 예약 기록이 있는 방식만.
#     멈춘 동안의 결제는 재고 서비스가 멈춘 시간이 들어 있다. 수량만·승인 먼저는 예약 기록이 없어 "기록 없음".
# 나. 예약 응답 시간(ReservationLatencyMeasurement): 재고 넉넉한 상품에 예약 요청을 하나씩 50건, 스레드 300개에서 한꺼번에 300건 보내 결제 서버 쪽에서 잰
#     응답 시간(시간 제한 10초로 늘림). 3번. 운영 읽기 시간 제한 1s 를 정한 근거로 쓴다.
# 두 번 실행했다(같은 코드). 첫 실행 앞의 시험 실행은 원복 ms 를 결제 결과를 남긴 때 기준으로 쟀다가, 그 자리에서 HTTP 비교가 결과를 남기기 전에 해제해
# 음수가 나와 요청을 보낸 때 기준으로 고치고 버렸다(아래에 없음).
